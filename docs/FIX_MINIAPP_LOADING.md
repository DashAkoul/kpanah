## 🎯 ریشه واقعی «Temporary server issue» که همچنان می‌آمد (نشست هشتم)

سه باگ پایین **واقعی** بودند و رفع شدند، اما علامتِ «Temporary server issue»
روی صفحه ورود همچنان ادامه داشت. علتش این بود:

**`VITE_API_BASE` در build تولید (production) ست نشده بود** → تمام درخواست‌های
API کلاینت **نسبی (relative)** می‌شدند و به اوریجین Pages
(`kpanah-lang.pages.dev`) زده می‌شدند. چون `_redirects` مسیر `/kpanah56/.../gate`
ندارد، Pages **404 با بدنه HTML** برمی‌گرداند → `response.json()` روی کلاینت
می‌شکند → `errors.server_error` = «Temporary server issue».

یعنی **کلاینت هرگز به Worker نمی‌رسید**؛ تمام تست‌هایی که «رفع شد» را تأیید
می‌کردند با curl مستقیم روی `workers.dev` بودند (نه از داخل مینی‌اپ).

**تأیید:** با یک endpoint دیاگنوستیک موقت ثابت شد Worker کاملاً سالم است
(insert/select `users`، `issueSession` کامل، امضای initData با خودِ bot token،
JWT round-trip، CORS preflight همه OK). مشکل فقط اتصال کلاینت→سرور بود.

**رفع:**
1. مقدار پیش‌فرض دفاعی در `apps/tma/src/lib/api.ts` (اگر `VITE_API_BASE` ست
   نشده باشد، به URL عمومی Worker وصل شود).
2. rebuild تولید با `VITE_API_BASE="https://kpanah-lang-edge.language-app-backend.workers.dev"`
   و redeploy روی Pages (طبق `SETUP_GUIDE.md:448`).
3. حذف endpoint دیاگنوستیک موقت و پاک‌سازی ردیف‌های تستی.

> ⚠️ اگر build بعدی بدون `VITE_API_BASE` انجام شود، باگ برمی‌گردد — مقدار
> پیش‌فرض دفاعی جلوی آن را می‌گیرد، اما ست‌کردنِ درست در build همچنان الزامی است.

## 🔴 باگ سوم (نشست هفتم) — «تلگرام query string را حذف می‌کند»

با اسکرین‌شات‌های BotFather مشخص شد ثبت `/newapp` **کامل و درست**
بود (Short name: `LinguaMasterAI`)، دکمه ربات کار می‌کرد و اپ باز
می‌شد — اما همچنان خطا می‌داد.

**ریشه:** توکن این‌طور به URL اضافه می‌شد:

```
https://kpanah-lang.pages.dev?t=<token>
                              ^^^^^^^^^^^^
```

**اما دکمه‌های `web_app` در تلگرام query string را حذف می‌کنند.**
تلگرام فقط آدرس ثبت‌شده را باز می‌کند، پس توکن **هرگز** به اپ نمی‌رسید.

**شاهد قطعی:** در KV دو توکن تازه وجود داشت — یعنی ربات درست کار
می‌کرد، ولی اپ هیچ‌وقت آن‌ها را مصرف نمی‌کرد.

**رفع:** تنها مسیر قابل‌اعتماد، `startapp` است:

```
url: "https://kpanah-lang.pages.dev?startapp=t_<token>"
        ↓ تلگرام تبدیل می‌کند
tgWebAppStartParam = "t_<token>"
        ↓ SDK
initDataUnsafe.start_param = "t_<token>"
```

قالب در پکیج **shared** تعریف شد (`buildStartParam` /
`extractTokenFromStartParam`) تا ربات و کلاینت از یک منبع حقیقت
بخوانند و دوباره واگرا نشوند. **۱۴ تست** این قرارداد را قفل می‌کند.

## 🔴 باگ دوم (نشست ششم) — «Temporary server issue»

بعد از رفع باگ اول، پیام خطا **عوض شد**:

| قبل | بعد |
|---|---|
| `Connection failed. Check your internet.` | `Temporary server issue. Try again shortly.` |

این **پیشرفت** بود: یعنی درخواست بالاخره به سرور می‌رسید.

**ریشه:** ناهمخوانی نام فیلدها بین امضا و خواندن JWT.

```typescript
// routes/auth.ts — امضا (باگ‌دار)
signJwt({ telegram_id: tgUser.id, sub: user.id })
//         ^^^^^^^^^^^ snake_case

// middleware/auth.ts — خواندن
context: { telegramId: claims.telegramId }
//                       ^^^^^^^^^^^ camelCase → undefined
```

`telegramId` همیشه `undefined` می‌شد → `requireUser()` خطای
`no identity` می‌داد → **همه** مسیرهای محافظت‌شده (`home`,
`get-today-lesson`, `progress`, …) با `404` شکست می‌خوردند.

**رفع:** امضا با همان نام‌هایی که خوانده می‌شوند:

```typescript
signJwt({ telegramId: tgUser.id, userId: user.id, uiLanguage: ... })
```

**تست قفل‌کننده:** دو تست در `middleware/__tests__/auth.test.ts`
(گروه `sign → verify → context contract`) که هم مسیر درست را تأیید
می‌کنند و هم مطمئن می‌شوند شکل باگ‌دار دیگر پذیرفته نشود.

## 🎯 چه چیزی عوض شد؟

**قبلاً:** اپ فقط با `initData` وارد می‌شد. اگر تلگرام آن را نمی‌فرستاد
(چون مینی‌اپ ثبت نشده یا از وب‌ویو ساده باز شده)، کاربر با پیام
گمراه‌کننده «اینترنت را بررسی کن» گیر می‌کرد.

**حالا:** ربات در `/start` یک **توکن ورود یک‌بارمصرف** می‌سازد و آن را
به لینک دکمه «🎓 باز کردن اپلیکیشن» اضافه می‌کند. سرور با آن توکن هویت
را تأیید می‌کند. **دیگر نیازی به ثبت مینی‌اپ نیست.**

```
کاربر → /start در ربات
      → ربات توکن می‌سازد و در KV ذخیره می‌کند
      → دکمه حاوی ?startapp=t_<token>
      → کاربر می‌زند → تلگرام آن را به tgWebAppStartParam تبدیل می‌کند
      → اپ بار می‌شود → api.ts توکن را از start_param می‌خواند
      → POST ?action=auth-link
      → سرور توکن را می‌سوزاند و JWT می‌دهد ✅
```

> ⚠️ **چرا `startapp` و نه `?t=`؟**
> دکمه‌های `web_app` در تلگرام query string را حذف می‌کنند. اگر
> `?t=<token>` بنویسیم، تلگرام فقط آدرس ثبت‌شده را باز می‌کند و توکن
> هرگز به اپ نمی‌رسد. `startapp` تنها مسیر قابل‌اعتماد است.

## 📱 الان چه کار کنم؟

فقط این دو کار را انجام دهید:

### ۱. در ربات دستور `/start` را بزنید

اگر قبلاً چت باز است، یک‌بار `/start` بفرستید تا **دکمه تازه** با توکن
ساخته شود. (توکن ۱۰ دقیقه اعتبار دارد و یک‌بارمصرف است.)

که **بعد از این پیام** ساخته شده است.

### ۲. روی «🎓 باز کردن اپلیکیشن» بزنید

از همان دکمه تازه. اپ باید مستقیم وارد شود.
